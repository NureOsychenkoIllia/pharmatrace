# PharmaTrace — простежуваність ліків і виявлення підробок

Система з трьох смарт-контрактів, ML-оракула, серверного API та вебінтерфейсу.
Партія ліків є NFT: виробник випускає її, дистриб'ютор і аптека передають
відповідальність, кожна дія пише подію в ланцюг. Оракул аналізує журнал передач
моделлю XGBoost, зберігає оцінку, версію моделі та хеш ознак у контрактах.

## Структура

```
project/
  src/                 контракти та інтерфейси
  test/                тести, газові стенди
  script/Deploy.s.sol  розгортання
  scripts/             seed, demo, атаки, перевірка цілісності
  ml/                  дані, ознаки, моделі, оракул, API
  notebooks/           аналіз даних
  web/                 вебінтерфейс (дві ролі)
  data/offchain/       позаланцюгові документи партій
  results/             метрики, графіки, журнали
  artifacts/           моделі та препроцесор
```

## Швидкий запуск

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
forge install foundry-rs/forge-std OpenZeppelin/openzeppelin-contracts
anvil
PRIVATE_KEY=<ключ anvil> VERIFIER=<адреса> ORACLE=<адреса> \
  forge script script/Deploy.s.sol:Deploy --rpc-url http://127.0.0.1:8545 --broadcast
./scripts/seed.sh
.venv/bin/python scripts/write_config.py
.venv/bin/uvicorn ml.api:app --host 127.0.0.1 --port 8000
```

Інтерфейс: `http://127.0.0.1:8000/app/index.html`.
Оракул: `ORACLE_PRIVATE_KEY=<ключ> .venv/bin/python -m ml.oracle --token 1 --clone`.
Для оновленого оракула розгорніть локальний стенд заново. Перед розгортанням
задайте `THRESHOLD_BPS` за порогом XGBoost у `results/model_metrics.json`,
помноженим на 10 000 та округленим до цілого. Оракул реєструє SHA-256 артефакту
моделі в `IncidentRegistry` і використовує окремий акаунт. SQLite зберігає
вхідні дані та підписані транзакції, тож повторний запуск перевіряє квитанцію
за тим самим хешем.

`seed.sh` імпортує демонстраційні метадані в SQLite. API перевіряє SHA-256
канонічного JSON за записом у контракті перед показом метаданих.

## Перевірки

```sh
forge test
forge coverage --report summary --exclude-tests
slither . --filter-paths "lib|test|script"
.venv/bin/python -m pytest
.venv/bin/python -m ml.generate_data
.venv/bin/python -m ml.train
.venv/bin/python -m ml.plots_data
.venv/bin/python -m ml.plots_models
.venv/bin/python -m ml.experiments
.venv/bin/python -m ml.plots_experiments
python3 scripts/cost_report.py
```

Для запуску API достатньо артефактів з репозиторію. Для повтору експериментів
після клонування виконайте `ml.train`, щоб зібрати артефакт Isolation Forest.
Партії, що перетинають часові межі між train, validation і test, вилучаються
повністю. Звіт експериментів містить сирі виміри п'яти прогонів сценарію та
кожного рівня навантаження.

## Контракти

- `ParticipantRegistry` — ліцензії виробників, дистриб'юторів, аптек, регулятора.
- `BatchToken` — ERC-721, скінченний автомат партії, передача відповідальності,
  поділ, відпуск, відкликання, рішення оракула.
- `IncidentRegistry` — інциденти, рішення моделі, підтвердження та відкликання.

## Модель загроз

| Компонент | Сценарій | Захід | Залишковий ризик |
|---|---|---|---|
| Серійний номер | Клон упаковки використовує наявний номер | Перевірка партії, оцінка аномальності, розгляд інциденту | Клон до першого спостереження може залишитися непоміченим |
| Передача партії | Учасник намагається записати передачу без згоди отримувача | Двоетапна передача і перевірка ролей | Власник дійсного ключа може підтвердити недостовірні дані |
| Мережа постачання | Учасники підтверджують неправдивий маршрут | Публічна історія і розгляд регулятором | Змова з правдоподібними даними може пройти перевірки |
| Оракул | Компрометований ключ підписує хибні рішення | Окрема роль, ротація ключа, підтвердження регулятором | Хибні оцінки до ротації залишаються в історії |
| Інциденти | Повтор рішення після підтвердження | Перевірка стану та повторне надсилання тієї самої підписаної транзакції | Авторизований оракул може створити новий інцидент |
| Сховище | Підміна метаданих у SQLite | Перевірка хешу за даними контракту | Походження метаданих залежить від автора початкового запису |
| Контракт партії | Надмірний масив поділу збільшує витрати виконання | Обмежена кількість дочірніх партій | Максимальний дозволений поділ коштує більше газу |
| Журнал подій | Чутливі дані потрапляють у публічний журнал | Передбачені хеші й зобов'язання замість особових полів | Передбачувані дані можуть розкриватися підбором |
